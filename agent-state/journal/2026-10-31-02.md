- AC-03 caught a REAL leak: the hand-typed `github_pat_` canary had 39 B's — one short of the

  pushed into a test backup repo. The exact-value grep of the clone flagged it. Root cause:

## GitHub push protection blocked the milestone push (new failure mode)
- The S4 gate passed (tree clean, history only the two documented benign hits, exact needle on)
  but GitHub REJECTED the push server-side: "Push cannot contain secrets" — push protection
  flagged the fake Stripe-key canary (tests/canaries.txt:8, tests/fixtures/home/.config/pay/
  stripe.txt:1) in the local commit. The commit never reached the remote (no leak, nothing to
  rotate); the local, unpushed commit was rewritten per the D7-permitted case.
- Root cause: canary-shaped DATA was committed so the tests could use it. GitHub cannot tell a
  fake sk_live_ value from a real one — and it should not have to.
- Fix (DECISIONS D9): the repository now commits only the clean fixture (home-clean/) plus a
  generator; build.sh injects all canaries into git-ignored tests/fixtures/home/ and writes
  git-ignored tests/canaries.txt at runtime; run-tests.sh auto-builds when they are missing.
  The generator source itself contains no pattern-shaped literals (rep() construction, split
  PEM headers, split URL-credentials string).
- Suite re-run after the restructure: 246 passed / 0 failed again.
