## Root cause analysis (code-verified)
- lib/collect.sh rice_collect_home walks with `find "$home/$d" \( -type f -o
  -type l \)` — find never descends into a symlinked dir: only the link entry.
- rice_consider records type=l with the LINK's size; no dereference anywhere.
- rice_stage_copy pipes tar WITHOUT -h → the link is staged as a link blob and
  git commits the target string as file content.

## Plan (D37) — see DECISIONS.md D37 for the locked design
Coverage rule is the key insight: links to content the backup ALREADY contains
(.vimrc -> .config/vim/vimrc, systemd *.wants) keep today's link semantics
(t06/t07/t15 stay valid); links to content NOT otherwise collected are followed
(content fetched under the link path + symlinks.tsv record + --relink).
