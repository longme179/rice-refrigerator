## Reasoning highlights
- The plan refuses to weaken the CLI promise: GUI = optional layer with startup
  self-check + per-distro install hints; single entrypoint preserved (a `gui`
  subcommand is a deferred optional backend touch-up).
- The one prompt that --yes cannot bypass (public-repo typed confirm) becomes a modal
  relay writing to child stdin — keeps the safety property while staying GUI-usable.
- Parsing the backend's human output is centralized in adapter.py with a raw-text
  fallback, so output drift can never crash or silently mislead the GUI, and a future
  --json can replace the parser without touching widgets.
- GUI testing is honest: adapter tests run headless here; anything needing a display is
  NOT RUN in the sandbox and listed as a manual checklist for the user.
