## Findings from the real dry-run (paths only, no user content)
1. BUG (P0, security): the Firefox XDG profile directory `.config/mozilla` is NOT in
   RICE_DENY_DIRS - only `.mozilla` is. The user's profile lives at
   `.config/mozilla/firefox/<profile>/` (weave/, storage/default/, formhistory.sqlite,
   Crash Reports all present in their exclusion list). Files there are excluded ONLY by
   the `*history*` filename glob and `*/cache/*` path patterns, which means
   cookies.sqlite, key4.db, logins.json, places.sqlite, sessionstore and non-cache site
   storage (IndexedDB/localStorage, often holding web-app tokens as opaque binaries)
   were all inside the 1334-file `.config/**` include set. Binary cookie/session stores
   do not match any L2 token shape, so the content scan cannot catch them - the deny
   list is the only layer that can, and it missed the directory. This is exactly the
   class of leak the tool promises never to allow. Fix: deny `.config/mozilla`,
   `.local/share/mozilla` (XDG data location), plus the fork homes `.zen`, `.floorp`,
   `.librewolf`, `.waterfox`.
2. BUG (P0, functional): the summary line `auth :` printed EMPTY. Root cause in
   lib/gitops.sh rice_auth_init: neither the RICE_TOKEN-from-env path nor the hidden
   prompt path ever sets RICE_AUTH_MODE=pat (only the gh paths set a mode). Because
   rice_auth_setup_git gates on mode=pat, the GIT_ASKPASS helper was never installed:
   a real (non-dry-run) PAT-mode push could not authenticate. The suite never caught it
   because tests either mock gh (mode=gh) or push to file:// remotes where no auth is
   needed. Fix + regression test (t21) added.
3. GAP (P1): 8 GiB total with a single warning line but NO breakdown - per-section byte
   counts and a top-15 largest-file list are needed so the user can see WHAT is big
   (on their machine most of it is the Firefox profile caught by bug 1).
4. GAP (P1): over-budget runs only warned; now a hard budget (default 1 GiB,
   RICE_TOTAL_MAX_BYTES override) refuses the real run without --allow-oversize.
5. GAP (P2): inventory plan summary omitted pipx and gnome-extensions; the collection
   side had pipx but not gnome-extensions. Both are now collected (gnome-extensions
   list + list --enabled) and shown.
6. GAP (P2): `.config/fcitx/dbus/<hash>-0` runtime peer-registration file was included;
   now L3 junk.
7. NOT bugs (verified normal): per-file deny entries under `.config/evolution/sources`,
   `*history*` glob catching formhistory.sqlite / notification-history.json (safe
   direction: those files can hold 2FA/autofill data), scan hits
   `.config/mango/scripts/networks.py [cred-assign]` (a real credential-looking
   assignment in a user script - correct exclusion) and firefox `signedInUser.json`
